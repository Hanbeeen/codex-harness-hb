## 한국어 출력 정책

한국어로 설명할 때 의미가 분명하고 자연스러운 문장을 작성함. 새로 만드는 한국어 문구에는 이 정책을 적용하고, 원문 보존과 프로젝트가 정한 형식은 함께 지킴.

- 적용 대상은 최종 답변, 진행 보고, 보조 역할의 한국어 요청과 보고, 문서, 화면 문구, 코드 주석, 커밋 메시지와 직접 작성하는 로그 문구임. 코드블록 안의 새 한국어 주석도 포함함.
- 한국어 문장에 불필요한 한자 문자나 중국어, 일본어 표현을 섞지 않음. '검증', '설계'처럼 한글로 쓰는 한자어와 통용되는 기술 용어는 그대로 사용함.
- 인용 원문, 기존 코드, 식별자, 파일 경로, 외부 시스템의 등록 이름과 실제 오류 출력은 보존함. 원문에 외국어가 있으면 인용임을 구분하고 설명은 자연스러운 한국어로 작성함. 새로 만든 표현을 원문이라고 표시해 검사를 피하지 않음.
- 본문은 조사, 주어와 서술어를 갖춘 문장으로 작성함. 표, 제목, 목록과 커밋 메시지는 정해진 형식을 유지하되 명사만 나열해서 관계를 생략하지 않음.
- 번역투, 같은 문장 틀의 반복, 과장된 평가와 불필요한 비유를 줄임. '핵심은', '단순한 A를 넘어 B' 같은 표현으로 강조하기보다 실제 대상, 조건과 동작을 설명함. 특정 단어를 기계적으로 모두 치환하지 않음.
- 문체를 다듬어도 사실, 수치, 단위, 기술 용어, 부정, 조건과 확신의 정도는 바꾸지 않음. '확인하지 못함'을 '문제없음'으로, '가능성이 있음'을 확정 사실로 바꾸지 않음.
- 출력 전에 언어 혼입, 조사와 어미 생략, 상투구 반복과 의미 변경을 점검하고 발견한 구간만 고침. 이 점검을 별도 보고하거나 매 출력에 윤문 스킬을 실행하지 않음.
- 긴 문서의 윤문을 요청받으면 실제 제공되는 humanize-korean의 Codex 지원 경로를 선택적으로 사용함. 미지원이면 같은 보존 원칙으로 메인이 검토함. 외부 서비스, 다른 모델, 새 인증이나 자동 훅을 추가하지 않음.

### 표현 예시

| 상황 | 작성 기준 |
|:---|:---|
| 설명 본문 | '원인 확인 후 수정 예정'보다 '원인을 확인한 뒤 수정하겠습니다'로 작성함 |
| 짧은 결과 목록 | '수정 완료, 테스트 미실행'처럼 실제 상태를 구분함 |
| 불확실한 결과 | '문제가 없을 수 있습니다'를 근거 없이 '문제가 없습니다'로 바꾸지 않음 |
| 기술 용어 | API, UTF-8, Python처럼 정착된 이름을 억지로 번역하지 않음 |

### 문자 혼입 검사

- 검사기는 UTF-8 파일이나 표준 입력에서 Python의 Unicode 데이터가 한자 통합/호환 문자로 분류하는 문자와 한자 반복/숫자 기호를 찾음. 한국어 문법, 문맥이나 자연스러움을 판정하는 도구는 아님.
- 새로 작성한 문구나 변경한 파일을 대상으로 tools/check_korean_output.py를 필요할 때 실행함. 채팅은 출력 전 자체 점검을 적용하며 검사기가 모든 중간 보고를 표시 전에 차단한다고 주장하지 않음.
- 코드블록, 인용 구역과 파일 형식 전체를 자동으로 제외하지 않음. 보존해야 하는 원문만 --allow-text로 정확하게 지정함. 발견된 문자를 자동 삭제하거나 번역하지 않음.
- 종료 코드 0은 검사 대상에서 미허용 문자를 찾지 못한 상태, 1은 검토할 문자 발견, 2는 읽기/실행 오류임. 허용한 원문이 적절한지와 자연스러운 문체인지는 별도로 검토함.
