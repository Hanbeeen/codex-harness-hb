# 과제 시작 요청

대괄호를 실제 값으로 바꿔 과제 수행 단계에서 사용함. 읽기 결과로 기술 스택이나 구현이 달라질 수 있으므로 먼저 사실을 확인함. 이 요청은 실제 과제 내용을 채운 작성본이 아님.

```text
목표: 필수 결과와 현재 프로젝트의 실행 시작점을 확인해줘.
맥락: 과제 안내 [위치], 작업 루트 [경로], 제공 데이터 [위치]가 기준이야.
제약: 먼저 파일 수정과 설치 없이 원문, 적용 중인 지침과 존재하는 실행/검사 명령을 확인해줘. 확정 사실, 질문, 가정과 비목표를 구분하고 실제 받지 않은 답변을 만들지 마.
git push는 인자/대상과 관계없이 절대 실행하지 마. 별칭/스크립트/다른 도구나 보조 역할을 통한 원격 쓰기 우회와 금지 확인용 실행도 제외해줘.
구현 범위를 제안할 때는 필수 요구와 구체적인 실패 조건을 충족하는 가장 단순한 기존 구조를 우선해줘. 미래 확장만을 위한 기능/추상화/의존성과 무관한 리팩터링은 추가하지 말고, 필요한 입력/권한 처리와 검증은 유지해줘.
완료 기준: 필수 요구마다 원문 출처와 입력/사전 상태, 행동, 관찰할 결과가 연결되고, 읽지 못한 파일과 미확인 조건이 남아 있음. 파일 존재와 명령 목록을 구현 완료나 검증 통과로 표시하지 마.
다음 판단: 핵심 흐름의 구현 범위와 사용할 검사를 제안하고, 답이 없어도 진행 가능한 작업을 구분해줘.
```

허용된 증거 위치도 확인함. 질문을 만든 것을 실제 답변을 받은 것으로 기록하지 않음. 이미 있는 프로젝트를 범용 템플릿으로 덮어쓰지 않음.

원문을 확인한 뒤 문서 정리가 도움이 되면 [요구와 상태 정리 요청](requirements-and-state.md)을 사용함. [빈 양식](../templates/README.md)은 실제 작성본과 구분하며 작성본은 공개 준비물과 분리된 허용 비공개 위치에만 둠. 이 시작 요청 자체는 새 문서 생성과 검사를 실행했다는 의미가 아님.
