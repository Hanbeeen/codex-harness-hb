# 사람 검토와 범위 승인

원문 요구와 실제 결과를 사람이 확인한 뒤 다음 작업 범위를 정할 때 사용함. 도구 권한 승인과 품질 검토는 별개임. 실제로 받지 않은 승인과 관찰을 만들지 않음.

## 검토 지점

| 시점 | 사람이 확인할 내용 | 다음 허용 범위 |
|:---|:---|:---|
| 구현 전 | 목적, 비목표, 중요한 데이터 규칙과 예상 결과 | 기능/파일과 바꾸지 않을 경계 |
| 기능 완료 | 실제 입력/결과, 오류와 미검증 | 수정 또는 다음 기능 |
| 요구/데이터/권한 변경 | 바뀐 근거, 영향과 대안 | 재검토 뒤 명시한 범위 |
| 확정 전 | 필수 동작, 저장, 현재 검사와 수정 주체 종료 | 안내에 맞는 사람이 수행할 최종 절차 |

승인한 기능 안의 보통 수정과 조회는 범위 안에서 이어갈 수 있음. 범위 확장과 중요한 의미 변경은 다시 확인함. 승인 횟수나 검토 문서의 길이를 성과로 삼지 않음.

## 검토용 반환 요청

```text
목표: 다음 작업 범위를 판단할 수 있게 현재 결과를 짧게 반환해줘.
맥락: 원문/요구 [위치], 수용 기준 [이름], 승인 범위 [기능/파일], 현재 코드/검사 [상태]야.
제약: 실제로 확인한 입력과 결과, 중요한 변경과 이유, 실패/미검증, 다음에 허용이 필요한 범위를 구분해줘. 없는 승인을 받았다고 기록하거나 범위를 먼저 넓히지 마.
완료 기준: 내가 원문과 실제 결과를 대조해 승인/수정/보류를 선택할 수 있음.
```

사람은 예시 입력을 직접 바꿔 보고 기대 결과와 비교함. AI의 완료 보고나 명령 성공만 읽고 승인하지 않음. 구현 이해는 입력에서 처리/상태/저장과 결과까지의 흐름, 선택 이유와 남은 한계를 설명하는 것으로 확인함.

실제 실패는 [QA 증거](qa-evidence.md), 요구와 판단은 [요구/상태 기록](requirements-and-state.md)에 연결함. 후속 서술형에는 이 요청문과 AI를 사용하지 않음.
