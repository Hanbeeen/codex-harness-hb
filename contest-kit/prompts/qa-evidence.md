# QA 검증과 실패 증거 요청

QA(Quality Assurance: 요구 충족 여부를 확인하는 작업) 대상은 본인 앱임. 역할과 도구가 실제 지원되는 경우에 사용하고, 검사할 코드와 테스트 상태를 먼저 고정함.

```text
목표: [수용 기준]을 본인 앱 [주소]에서 검증해줘.
맥락: 원문/실제 답변 [위치], 코드 기준 [상태], 입력/사전 상태 [값], 사람이 확인한 예상 결과 [내용], 허용 증거 위치 [서버 내 경로]가 기준이야.
범위: 소스, 테스트와 설정을 수정하지 마. 기대값을 낮추거나 검사를 삭제/건너뛰어 통과시키지 마. 명령 검사는 verification_runner 또는 메인에서, UI 검증은 qa-ui의 Chrome DevTools MCP로 분리해줘. Computer Use와 시험/감독/제출/서술형 화면, 외부 전송은 제외해줘.
실패 수집: 실제 UI 실패는 수정/새로고침/초기화 전에 본인 앱 화면과 재현 조건, 예상/실제, 콘솔/요청 오류를 보존해줘. 명령 실패는 명령, 작업 위치, 종료 코드와 원문 출력을 보존해줘.
수집 실패: 캡처나 기록이 실패하면 즉시 오류와 미수집 항목을 보고하고 안전한 대체 근거를 남겨줘. 성공한 것으로 꾸미지 마.
보존: 실패 원본을 유지하고 같은 식별자로 수정/재검증을 연결해줘. 통과한 검사에는 별도 증거 파일을 만들지 마.
완료 기준: 해당 기능의 목록/건수/내보내기와 빈 결과 뒤 복구를 대조하고 제품 결함과 검사 조건/환경 문제를 구분해줘. 사례별 통과/실패/미실행, 실제 근거 위치, 확인하지 못한 범위가 구분됨. 도구가 없으면 설치하거나 우회하지 말고 대체 방법을 보고해줘.
```

기대한 400/403 응답은 요구에 맞으면 검증 성공일 수 있음. 화면 검사와 계산/데이터 검사는 서로 대신하지 않음. 이 묶음에는 qa-ui 역할 정의가 있지만 MCP 연결은 포함하지 않음. 역할 자동 인식이 안 되면 roles/qa-ui.md를 메인에서 순차 수행하고 독립 검토와 구분함.
