# 보안 검토 요청

구현한 작은 흐름이 동작한 뒤 또는 입력, 권한과 저장 경계가 바뀌었을 때 사용함. 과제 수행 중의 요청문이며 후속 서술형에는 사용하지 않음. 코드 검토만 필요한 상태에서는 실행 허용을 '없음'으로 채움.

```text
목표: [본인 앱의 기능/변경 범위]에서 실제 보안 위험을 검토해줘.
맥락: 작업 폴더 [경로], 요구 원문 [위치], 코드 기준 [상태], 읽을 파일 [범위], 남은 시간 [값]이 기준이야.
실행 허용: [없음 또는 기존 검사 명령과 허용 앱 주소/경로/메서드]. 사용할 합성 데이터와 예상 결과는 [내용], 시간/요청 횟수 한도는 [값], 허용 증거 위치는 [현재 실행 환경의 경로]야.
제약: roles/security_reviewer.md의 검토와 결과 구분을 적용하고, 지원되는 역할을 사용할 때만 security_reviewer에 맡겨줘. 별도 역할을 쓰지 않는 세션에서는 같은 원문을 메인에서 순차 수행하고 독립 검토로 표시하지 마.
제약: 파일 수정, 도구 설치, 외부 전송, 개인 키/모델/권한 변경과 시험 화면 조작은 제외해줘. 비밀값을 읽거나 출력하지 말고 값이 없는 위치와 경로로 보고해줘.
완료 기준: 실제 재현, 코드로 확인한 위험, 추가 확인 후보와 미검증이 분리되고 근거 위치, 실행 여부, 영향, 수정 방향과 재검증 조건이 남아 있음.
중단 기준: 범위 밖 접근, 파괴적 요청 또는 비밀값 노출이 필요하면 해당 검증을 중단하고 사유와 안전한 대체 근거를 반환해줘.
```

역할 정의는 [security_reviewer.toml](../.codex/agents/security_reviewer.toml), 자동 인식 미지원 또는 순차 수행 시 원문은 [security_reviewer.md](../roles/security_reviewer.md)임. 실제 대상에서 경로를 확인해 요청문의 roles/security_reviewer.md를 치환함. 파일 정의만으로 도구, 호출 성공과 별도의 읽기 전용 격리가 생기지 않음.

검색된 문자열만으로 취약점을 확정하지 않음. 위험 연산까지 실제로 연결되는지, 보호 수단이 있는지와 어떤 입력을 누가 통제하는지 확인함. 실행 허용이 없거나 도구가 없으면 정적 검토만 수행하고 동적 검증을 통과로 표시하지 않음.

실제 실패는 [QA 증거 요청](qa-evidence.md)과 같은 식별자로 연결함. 본인 앱의 UI(User Interface: 화면과 조작 기능) 실패는 수정 전에 qa-ui의 실패 캡처가 필요함. 캡처 도구가 없으면 미수집으로 보고함. 비밀값이 있는 응답과 화면은 수집 범위를 제한하고, 명령 실패는 명령과 종료 코드 및 비밀값을 제외한 출력을 남김. 통과 검사의 별도 증거 파일은 만들지 않음.
