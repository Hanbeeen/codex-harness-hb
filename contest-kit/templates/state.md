## 구현과 검증

| 기준/검사 이름 | 실제 코드 위치 | 구현 상태 | 검증 상태와 최근 관찰 |
|:---|:---|:---|:---|
| [요구 정리와 같은 기존 ID 또는 기준 이름] | [실제 파일:라인. 없으면 미구현, 읽지 못했으면 미확인] | [미구현 / 진행 중 / 구현됨 중 선택] | [미검증 / 통과 / 실패 / 미실행 중 선택, 시점, 입력/코드 기준, 명령과 종료 코드 또는 화면 행동, 실제 관찰/사유] |

구현 상태와 검증 상태는 별도로 판정함. 미검증은 아직 확인하지 않은 상태, 미실행은 도구 부재나 제약으로 수행하지 못한 상태임. 통과와 실패는 [수용 기준](prd.md)의 예상 결과와 실제 관찰을 비교한 경우에만 사용함. 최신 코드가 검사 당시와 다르면 영향받는 결과를 현재 통과로 옮기지 않음.

## 실패와 재검증

실제 실패가 있을 때 아래 묶음을 추가함. 기존 실패 ID나 검사 ID를 재사용하고, 최초 실패와 재검증 행을 덮거나 지우지 않음. 원본 실패 기록이 이미 있으면 그 위치를 연결하고 필요한 요약만 남김.

- 최초 실패 조건: [시점, 코드/데이터 상태, 재현 입력/사전 상태와 행동]
- 예상과 실제: [수용 기준의 예상], [관찰한 실제 결과]

- 증거 수집 상태: [보존 위치와 확인 결과 또는 미수집 사유/도구 오류와 대체 근거]
- 원인과 수정: [확인한 원인 근거와 실제 변경 파일:라인. 원인 미확인이면 미확인]

| 재검증 시점과 코드/데이터 상태 | 같은 조건과 영향받는 흐름 | 실행 결과와 판정 |
|:---|:---|:---|
| [수정 뒤 실제 검사 시점과 대상 상태] | [최초 재현 조건, 함께 확인할 영향 범위] | [실제 명령과 종료 코드 또는 화면 행동, 관찰 결과, 통과/실패/미실행과 사유] |

실패는 수정, 새로고침과 상태 초기화 전에 보존함. 도구/캡처 실패와 앱 결함을 구분하고 즉시 알림. 통과한 검사마다 별도 증거 파일을 쌓지 않음.
