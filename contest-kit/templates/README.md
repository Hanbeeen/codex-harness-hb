# 요구와 상태 양식

이 폴더는 재사용 가능한 빈 양식임. 실제 과제 요구, 코드 위치, 업무 답변이나 검증 결과를 담은 작성본이 아님. 양식 파일이 있다는 사실은 요구 충족이나 검증 통과의 근거가 되지 않음.

## 파일의 책임

| 파일 | 기록할 내용 |
|:---|:---|
| [prd.md](prd.md) | 원문 요구와 출처, 사실/질문/가정, 핵심 흐름, 수용 기준과 비목표 |
| [decisions.md](decisions.md) | 구현을 바꾸는 선택의 채택/기각 이유와 남은 한계 |
| [state.md](state.md) | 실제 코드 위치, 현재 구현/검증 상태, 남은 실패와 재검증, 다음 행동 |

PRD(Product Requirements Document: 제품 요구사항 문서)는 원문을 찾고 구현할 결과를 정리하는 도구임. 제공 안내와 실제 받은 답변보다 높은 권위를 갖지 않음. 서로 충돌하면 출처를 확인하고 정리를 바로잡음.

## 사용과 보관

- 별도 문서가 도움이 될 때만 사용함. 짧은 기존 기록으로 충분하면 파일을 추가하지 않음.
- 실제 작성본은 공개 준비물 폴더와 분리된 허용 비공개 작업 위치에 둠. 이 폴더의 빈칸에 실제 과제 내용을 바로 채우지 않음.
- 사용할 때 위 파일을 같은 폴더에 `prd.md`, `decisions.md`, `state.md`라는 이름으로 함께 복사함. 문서 구분을 '실제 작성본'으로 바꾸고 대괄호를 확인한 값으로 채움. 확인하지 못한 값은 '미확인'과 사유를 적음.
- 파일 사이 링크는 같은 폴더의 고정 파일명만 사용하므로 함께 복사해도 유지됨. 일부만 쓰면 존재하지 않는 문서 링크를 지우고 기존 기록의 실제 위치로 바꿈.
- 기존 요구 이름이나 검사 ID(Identifier: 식별자)를 그대로 재사용함. ID가 없으면 짧은 기준 이름으로 연결하고 문서마다 새 번호 체계를 만들지 않음.
- 요구와 예상 결과는 `prd.md`, 선택 이유는 `decisions.md`, 구현 위치와 관찰 결과는 `state.md`에 한 번씩 기록하고 서로 연결함. 로그와 원문 전체를 반복 복제하지 않음.
- 요구가 바뀌면 출처, 영향받는 기준과 현재 상태를 갱신함. 과거 실패/검사 결과는 지우지 않고 당시 코드/입력 조건과 현재 적용 여부를 남김.
- 이 저장소에서 커밋 대상은 재사용 빈 양식뿐임. 실제 PRD, 설계, 계획과 과제 작성본은 커밋하지 않으며 공개, 외부 전송과 준비물 묶음에 포함하지 않음.

실패 원문과 본인 앱의 실패 화면은 시작할 때 확인한 허용 증거 위치에 보존함. 비밀값, 개인 링크와 감독/제출 화면을 기록하지 않음. 증거 수집 실패는 앱 실패와 구분하고 미수집 사유를 남김.
