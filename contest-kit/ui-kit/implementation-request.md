# UI 구현 요청문

메인이 실제 UI(User Interface: 화면과 조작 기능) 구현을 요청할 때 사용하는 텍스트임. 준비물 작성 단계에서 실행하라는 지시가 아님. 대괄호를 실제 값으로 채우고 해당 없는 줄은 지움. 업무 답변, 성능과 도구 지원을 지어내어 채우지 않음.

## 설계 검토 요청

```text
ui_designer를 선택적으로 사용해 지정한 화면의 설계 판단을 검토해줘.
목표: [이용 대상]이 [입력]으로 [작업]을 끝내고 [결과]를 확인할 수 있게 해줘.
원문: [과제 안내/업무 답변의 파일과 구간]. 제공 코드: [허용한 경로].
확정 사실: [제공 구조와 필수 결과]. 미확인: [답 없는 질문].
범위: [화면/핵심 흐름]. 제외: [추가하지 않을 기능]. 남은 시간: [실제 값].
목적, 정보 순서, 주 동작과 상태별 예상 결과를 제안하고 근거 위치와 선택 이유를 반환해줘.
파일 수정과 브라우저 실행은 하지 말고, 실제 조작이 필요한 사례를 메인에 반환해줘.
역할 미지원이면 같은 원문을 메인이 순차로 검토하고 독립 호출과 구분해줘.
```

## 필수 흐름 구현 요청

```text
목표: [입력]부터 [처리]와 [결과 확인]까지 과제의 필수 흐름을 실제 동작하게 해줘.
원문: [파일과 구간]. 수용 기준: [입력, 행동과 관찰할 성공/실패 결과].
대상: [앱 경로와 화면]. 제공 구조: [확인한 스택과 실행 방법].
확정한 화면 판단: [정보 순서, 주 동작과 상태]. 미확인: [답 없는 항목].
기존 구조, 데이터 계약과 설치된 스타일 도구를 유지하고 지정한 범위에서 구현해줘.
초기, 처리 중, 성공, 빈 데이터, 조건 불일치와 오류 중 이 흐름에 해당하는 상태를 처리해줘.
목록, 건수, 조건과 상세가 같은 결과를 표시하고 실패 때 입력과 이전 정상 데이터를 정한 기준대로 보존하게 해줘.
예시와 실제 결과, 적용과 저장을 구분하고 레이블, 키보드 포커스와 좁은 화면의 필수 조작을 확인해줘.
설치된 frontend-design 스킬이 실제 사용 가능하면 해당 지침만 참고하고, 없으면 이 요청과 로컬 검토 기준으로 진행해줘.
완료 기준: [필수 검사 명령과 예상 결과], [메인이 승인한 qa-ui 사례의 예상/실제 일치]. 미실행 범위는 분리해줘.
```

## 기존 화면 개선 요청

```text
목표: [이미 동작하는 화면]에서 [읽기/조작 문제]를 해결해 [관찰 가능한 결과]가 나오게 해줘.
근거: [실패 입력/화면 또는 파일:라인]. 지켜야 할 동작: [핵심 흐름과 수용 기준].
범위: [수정 허용 파일/화면]. 유지할 구조: [기존 스타일, 데이터 계약과 저장 기준].
정보 순서, 문구, 간격, 넘침과 상태 전달 중 근거 있는 문제만 수정해줘.
새 기능, 새로운 테마와 의존성 추가는 제안으로 분리하고 메인의 판단을 받아줘.
React 검토 지침이 있으면 실제 요청 대기, 파생 상태와 렌더링 문제가 있는 경로에만 적용해줘.
측정하지 않은 성능 향상을 수치로 주장하지 말고 변경한 흐름의 검증을 다시 요청해줘.
완료 기준: [같은 입력에서 예상 화면], [회귀를 확인할 기존 검사와 결과].
```

React는 화면을 컴포넌트로 구성하는 라이브러리이고, 렌더링은 상태를 화면에 그리는 과정임. 파생 상태는 원본 데이터와 조건으로 계산할 수 있는 값임. 화면 건수와 목록을 따로 바꾸는 대신 같은 결과에 맞추는 판단에 해당함.

처음 만드는 웹앱의 기본 후보는 Next.js와 TypeScript이며, 제공 구조가 있으면 유지함. Python 전용 처리나 제공 Python 서버가 필수일 때만 FastAPI를 검토함. 이 문구를 스킬을 쓰기 위한 프레임워크 교체 지시로 사용하지 않음.

실제 화면 검증은 [화면 검증 인계](qa-handoff.md)를 채운 뒤 메인이 qa-ui에 요청함. 도구 연결이 없으면 설치나 권한 변경으로 우회하지 않고 미실행과 허용된 수동 확인 범위를 남김.
