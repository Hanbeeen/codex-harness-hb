# UI 작업 준비물

원문 요구를 실제 화면 작업과 검증 사례로 옮기는 로컬 텍스트 준비물임. 앱 코드, UI(User Interface: 화면과 조작 기능) 템플릿, 설치된 스킬과 실행된 검증은 포함하지 않음. 전역 설치와 제공 환경 등록을 자동 수행하지 않음.

목적은 평가자가 필수 기능을 실제로 확인할 수 있게 하고, AI(Artificial Intelligence: 인공지능) 제안을 채택하거나 버린 이유를 설명할 수 있게 하는 것임. 시각적 독창성이나 스킬 사용이 공식 배점이라는 근거는 확보하지 못했음.

## 사용할 자료

| 자료 | 사용할 시점 | 얻을 결과 |
|:---|:---|:---|
| [설계 입력](design-brief.md) | 원문과 실행 구조를 읽은 뒤 | 목적, 핵심 흐름과 상태별 수용 기준 |
| [구현 요청](implementation-request.md) | 메인이 실제 UI 구현을 승인받은 뒤 | 필수 흐름과 상태를 연결하는 요청문 |
| [검토 기준](review-checklist.md) | 구현 제안 또는 기존 코드를 검토할 때 | 근거 있는 위험 후보와 확인할 실행 사례 |
| [화면 검증 인계](qa-handoff.md) | 본인 앱이 실행되고 허용 경계가 확정된 뒤 | qa-ui에 전달할 재현 가능한 사례 |
| [ui_designer 원문](../roles/ui_designer.md) | 목적, 정보 순서와 상태 판단이 필요한 경우 | 파일을 바꾸지 않는 설계 제안 |
| [ui_designer 역할 파일](../.codex/agents/ui_designer.toml) | 제공 환경이 사용자 정의 역할을 지원하는 경우 | 같은 Markdown 원문을 담은 역할 정의 |

## 적용 방식

원문, 제공 코드와 기존 지침을 먼저 읽음. 문서의 빈칸을 채워 현재 필요한 요청문만 사용하고, 준비물을 통째로 실행 절차로 강제하지 않음. 새로운 웹앱의 기본 후보는 Next.js(React 기반 웹 프레임워크)와 TypeScript(JavaScript에 타입 검사를 더한 언어)임. 제공 프로젝트가 있으면 유지하고, Python 전용 처리나 제공 Python 서버가 필수일 때만 FastAPI(Python 기반 요청 처리 프레임워크)를 검토함.

ui_designer는 선택적 읽기 중심 역할임. 실제 수정과 통합은 메인이 담당함. 앱 실행과 화면 검증은 [qa-ui](../roles/qa-ui.md)의 허용 범위에서 별도로 요청함. Computer Use와 Chrome DevTools MCP(Model Context Protocol: 모델과 도구의 연결 규약)를 이용한 본인 앱 검증을 동일시하지 않음. ui_designer는 둘 다 실행하지 않음.

역할 파일은 name, description, developer_instructions만 사용함. 모델, 권한과 MCP 연결은 부모를 따름. 파일 수정 금지는 행동 지침이며 별도 보안 격리가 아님. [공식 Codex 역할 문서](https://learn.chatgpt.com/docs/agent-configuration/subagents)의 형식에 맞춘 준비물이며, 파일 존재가 실제 등록과 호출 성공을 뜻하지 않음.

프로젝트에 이미 같은 역할 파일이나 지침이 있으면 내용을 읽고 충돌을 메인에 알림. 자동 덮어쓰기, 전역 복사와 config.toml 변경은 하지 않음. 역할이 지원되지 않으면 Markdown 원문을 메인에게 전달해 순차 검토하고 독립 역할 호출과 구분함.

## 검증 상태

구문 검사, 역할 원문 일치, 내부 링크와 금지 문자 검사는 텍스트 자산의 일관성 검사임. 실제 역할 호출, 앱 구현, 브라우저 연결, 접근성 측정, 결함 탐지 성능과 Cofa 호환성은 별도 실행 대상이며 아직 확인하지 않았음.

외부 스킬과 플러그인의 조사 이력이나 설치물은 포함하지 않음. 실제 요구와 제공 도구를 기준으로 필요한 지침만 사용함.
