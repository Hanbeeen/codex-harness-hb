# 화면 검증 인계

ui_designer는 검증할 사례를 제안하고 메인이 실행 경계와 입력을 확정함. 이 문서는 [qa-ui](../roles/qa-ui.md)의 입력 준비물이며 별도 검증 엔진, 서버 실행기와 브라우저 자동화 스크립트가 아님.

## 메인이 채울 실행 경계

| 항목 | 전달할 실제 값 |
|:---|:---|
| 허용 대상 | [실행 중인 본인 앱의 실제 주소와 허용 경로] |
| 코드 기준 상태 | [커밋 또는 변경 상태 식별값. 검사 중 수정 여부] |
| 서버/데이터 상태 | [실행 확인, 초기 데이터와 초기화 기준] |
| 허용 조작 | [비파괴 동작과 허용된 합성 테스트 계정] |
| 제외 대상 | [시험 플랫폼, 감독, 신분증, 제출과 후속 서술형 화면] |
| 수용 기준 | [원문 위치와 관찰할 성공/실패 결과] |
| 증거 위치 | [제공 서버 안의 쓰기 허용 EVIDENCE_ROOT] |
| 호출 예산 | [현재 남은 시간과 도구 호출 제한] |
| 사용 도구 | [실제로 연결된 Chrome DevTools MCP 도구] |

주소, 실행 여부, 증거 위치와 예상 결과가 미확인이면 메인이 먼저 보완함. 개인 PC 경로와 임의 포트가 제공 환경에도 있다고 가정하지 않음. 로그인 없는 앱에 계정 검사를 추가하지 않음. 역할은 서버를 시작/종료하거나 소스/설정을 수정하지 않음.

## 사례 양식

각 사례는 요구와 실제 조작을 연결함. 디자인 취향 대신 결과와 데이터 관계를 적음.

```text
id: [기존 식별자 또는 새 사례 ID]
requirement_ref: [원문 파일과 구간]
preconditions: [데이터, 입력과 선택 상태]
action: [범위 안에서 실제 수행할 조작]
expected: [화면 값, 상태 변화와 다음 행동]
data_invariant: [바뀌어도 유지돼야 할 데이터 관계]
reset: [허용된 초기화 방법 또는 초기화 불필요]
```

data_invariant는 조작 전후에 지켜야 할 관계임. 예를 들어 필터가 바뀌어도 원본 데이터가 사라지면 안 되고, 목록이 바뀌면 표시 건수와 상세가 현재 결과에 맞아야 함. 사례에 실제로 해당하는 관계만 적음.

## 메인에 반환할 사례 후보

| 조건 | 조작 후보 | 확인할 예상 결과 |
|:---|:---|:---|
| 필수 흐름 있음 | 실제 입력을 넣고 주 동작 실행 | 요구한 결과와 완료 범위가 맞음 |
| 검색/필터 있음 | 일치 조건, 불일치 조건과 초기화 | 목록/건수/상세가 일치하며 원본 유지 |
| 입력 검증 있음 | 형식 또는 필드가 잘못된 입력 | 고칠 위치가 보이고 입력과 이전 데이터 유지 |
| 비동기 요청 있음 | 처리 시작 뒤 성공/허용된 실패 관찰 | 중복 처리 기준을 지키고 종료 뒤 재조작 가능 |
| 상세 선택 있음 | 항목 선택 뒤 조건 변경 | 보이지 않는 항목의 이전 상세가 남지 않음 |
| 필수 조작 있음 | 키보드로 입력, 실행과 결과 확인 | 포커스를 볼 수 있고 조작을 끝낼 수 있음 |
| 작은 화면 대응 요구 | 허용된 너비에서 같은 흐름 수행 | 필수 값과 조작을 잃지 않음 |
| 긴 내용 입력 가능 | 긴 이름 또는 오류 표시 | 내용이 다른 값과 조작을 가리지 않음 |

앱에 없는 기능은 추가하지 않고 해당 없음으로 반환함. 서버 실패를 만들기 위해 프로세스를 종료하거나 설정/응답을 바꾸지 않음. 허용된 합성 재현 경로가 없으면 실패 상태의 실행 검증을 미실행으로 남김.

## 복사용 요청

```text
qa-ui로 지정한 본인 앱과 전달한 사례만 검증해줘.
허용 주소/경로: [실제 값]. 코드 기준 상태: [실제 값]. 데이터: [합성 입력과 사전 상태].
수용 기준과 사례: [위 양식으로 작성한 실제 사례].
허용 조작: [실제 범위]. EVIDENCE_ROOT: [허용 위치]. 호출 예산: [실제 값].
Computer Use 없이 실제 연결된 Chrome DevTools MCP 도구만 사용해줘.
실제 UI 실패는 수정, 새로고침과 초기화 전에 실패 화면과 재현/오류 근거를 보존해줘.
도구 또는 캡처 실패는 앱 결함과 분리해 즉시 알리고, 통과 화면의 증거 파일은 만들지 마.
시험 플랫폼, 감독, 신분증, 제출과 후속 서술형 화면은 열거나 조작하거나 캡처하지 마.
도구 연결이나 서버가 없으면 설치/실행/설정 우회를 하지 말고 관련 사례를 skipped로 반환해줘.
결과는 qa-ui 계약의 worker, findings, tcs, unreviewed 구조로 반환해줘.
```

각 사례의 pass는 실제 관찰이 기준에 맞았다는 뜻임. fail은 실제 요구 위반이고 skipped는 수행하지 않았다는 뜻임. 예상된 오류 응답은 올바른 거부 동작일 수 있으므로 상태 코드만으로 결함을 정하지 않음. 수동 확인이 대신 수행됐다면 자동 역할 결과와 섞지 않고 조작 주체, 확인한 결과와 미확인 범위를 남김.
