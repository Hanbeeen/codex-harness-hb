# UI 설계 입력

메인이 원문 요구를 읽고 이 문서의 필요한 칸만 채움. 문서를 채우는 것 자체보다 실제 입력에서 결과까지 이어지는 필수 흐름을 우선함. 확인하지 않은 값은 미확인으로 남기며 요약이 과제 원문을 덮지 않게 함.

## 목적과 경계

| 항목 | 작성할 내용 |
|:---|:---|
| 요구 원문 | [파일과 구간, 또는 제공 안내의 식별 위치] |
| 실제 이용 대상 | [누가 어떤 상황에서 쓰는지. 안내에 없으면 가정 표시] |
| 끝낼 작업 | [입력을 받아 어떤 결과를 확인하거나 바꾸는지] |
| 필수 결과 | [평가자가 관찰할 출력, 상태 변화와 근거] |
| 제공 구조 | [기존 실행 명령, 화면, 언어와 사용 가능한 도구] |
| 데이터 기준 | [원본 위치, 예시/실제 구분, 단위, 날짜와 표시 기준] |
| 저장 기준 | [적용/저장 구분, 새로고침과 재시작 때 보존 여부] |
| 제외 범위 | [과제에서 요구하지 않은 기능과 보류한 제안] |
| 남은 질문 | [답에 따라 구현 또는 통과 기준이 달라지는 질문] |

## 핵심 흐름

한 흐름에서 입력, 주 동작과 완료 결과를 연결함. '화면이 예쁨' 대신 관찰 가능한 성공 상태를 적음.

| 요구 근거 | 사전 상태와 입력 | 주 동작 | 성공 결과 | 실패와 복구 |
|:---|:---|:---|:---|:---|
| [원문 위치] | [데이터와 입력] | [실제 행동 이름] | [값, 화면과 데이터 변화] | [실패 뒤 유지할 것과 다음 행동] |

정보는 실제 이용 대상의 작업 순서에 맞춰 배열함. 첫 화면의 설명보다 조작이 우선인 작업이라면 현재 조건, 입력/주 동작과 결과를 먼저 보여줌. 비교가 필요한 값에는 단위와 기준을 함께 적음. 과제에 없는 통계, 상태와 버튼을 보기용으로 채우지 않음.

## 상태별 수용 기준

수용 기준은 끝났다고 판단할 관찰 가능한 조건임. 아래는 상태 분류이며 앱에 전부 추가하라는 목록이 아님. 해당하지 않으면 이유를 적고 제외함.

| 상태 | 진입 조건 | 보여줄 정보 | 보존할 것 | 다음 행동과 실패 기준 |
|:---|:---|:---|:---|:---|
| 초기 | [아직 입력 전] | [예시 여부와 시작 동작] | [원본 데이터] | [실제 처리한 것처럼 보이면 실패] |
| 처리 중 | [비동기 작업이 진행됨] | [무엇을 처리 중인지] | [입력과 이전 결과의 관계] | [중복 요청, 취소와 대기 종료의 요구 기준] |
| 성공 | [요구한 처리 완료] | [결과와 완료 범위] | [확정된 데이터] | [적용을 저장이라고 표시하면 실패] |
| 원본 데이터 없음 | [원본 항목이 없음] | [데이터가 없는 이유 또는 입력 안내] | [입력 상태] | [검색 조건 초기화로 해결된다고 오인하면 실패] |
| 조건에 맞는 결과 없음 | [원본은 있으나 검색/필터와 불일치] | [현재 조건과 결과 없음] | [원본 데이터] | [조건 변경 또는 초기화] |
| 잘못된 입력 | [형식/필드/업무 규칙 위반] | [위치와 고칠 내용] | [작성한 입력과 이전 정상 데이터] | [정한 보존/반영 계약과 다르면 실패] |
| 처리 실패 | [연결, 서버 또는 예상 밖 응답] | [실패 범위와 재시도 가능 여부] | [요구에서 정한 이전 상태] | [예시 결과로 조용히 바꾸면 실패] |

## 조작과 읽기

- 행동 이름: 버튼 문구가 실제 처리와 완료 메시지에 대응함. 검색, 적용, 저장과 삭제를 서로 바꾸어 쓰지 않음.
- 입력: 레이블과 안내가 있고 오류 위치를 식별할 수 있음. 입력 예시 문구만으로 레이블을 대신하지 않음.
- 키보드: 필요한 조작에 순서대로 도달하고 포커스(키보드 입력을 받는 현재 위치)를 볼 수 있음. 대화상자가 있으면 닫은 뒤 위치와 다음 동작을 정함.
- 상태 전달: 색 외에 글자나 기호로 상태를 구분함. 처리 결과 변화가 보조기술에도 전달돼야 하는지는 구현 검토와 실행 검증으로 나눠 확인함.
- 내용 변화: 긴 이름, 긴 오류와 큰 숫자를 넣어도 필수 값과 조작이 가려지지 않는 기준을 적음. 실제 업무와 무관한 많은 데이터를 만들어 규모를 과장하지 않음.
- 작은 화면: 허용된 미리보기에서 확인할 너비를 메인이 정함. 표의 가로 이동이 필요하면 안내하고 주요 조작이 화면 밖으로 사라지지 않게 함.

## 메인에 반환할 판단

채택할 정보 순서와 이유, 과제에서 제외할 상태, 아직 답이 필요한 질문과 [화면 검증 인계](qa-handoff.md)에 옮길 사례를 반환함. 코드에서 추정한 위험과 실제 앱에서 확인한 실패를 분리함. 실제 화면과 키보드를 확인하지 않았다면 그 검증을 통과로 표시하지 않음.
