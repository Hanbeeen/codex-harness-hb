# 설계와 AI 협업 설명 답안 템플릿

설계 이유, 구체적인 동작 원리, AI(Artificial Intelligence: 인공지능)와 조정한 내용과 이유를 설명하는 사전 연습 자료임. 질문마다 바꿔 쓸 수 있는 답안 틀과 한 문단으로 완성한 예시를 함께 제공함. 공식 기출, 채점 기준이나 공식 모범 답안은 아님.

## 사용 기준

- 답안 틀의 대괄호를 실제 요구, 구현과 관찰로 바꿈. 예시의 기술 선택이나 업무 규칙을 그대로 자신의 구현이라고 설명하지 않음.
- 완성 예시는 모두 가상의 구현과 협업 과정을 설정한 창작임. 실제 체험이나 특정인의 작업 이력을 기록한 것이 아님.
- 답안은 질문에 대한 결론으로 시작하고 선택 이유, 처리 과정과 구체적인 사례를 이어 붙임. 질문과 무관한 항목을 모두 넣으려고 늘리지 않음.
- 오류를 발견하거나 AI 제안을 수정한 일이 없으면 그 사실을 적음. 그럴듯한 실패, 반박이나 검증 결과를 새로 만들지 않음.
- 구현한 사실, 실제 확인한 결과와 확인하지 못한 조건을 구분함. 함수 이름을 기억하지 못하면 역할과 데이터 흐름을 설명하고 이름을 지어내지 않음.
- 사전 연습에 사용하며, AI나 참고 자료 사용이 제한된 실제 답변 단계에서는 해당 안내를 따름.

## 공통 예시의 설정

아래 완성 예시는 담당자가 미처리 업무 요청과 기한 초과 여부를 확인하는 작은 조회 서비스를 가정함. 요청 식별자인 `request_id`가 같으면 가장 큰 개정 번호인 `revision`을 현재 기록으로 사용함. 서로 다른 내용의 최대 개정 번호가 겹치면 임의 선택을 하지 않고 충돌로 안내하는 정책을 확인받았다고 가정함. 화면은 검색과 부서/상태 필터, 요약 건수, 목록과 상세로 구성함.

기한은 제공 데이터의 기준 시각인 `as_of`와 `due_at`을 시각 값으로 해석해 비교함. 미처리 요청의 기한이 기준 시각보다 앞설 때 기한 초과로 분류하고, 정확히 같으면 초과로 세지 않음. 기한이 없거나 잘못됐으면 요청은 유지하면서 기한 판단 불가로 표시함. 날짜에 시간대가 없으면 임의로 해석하지 않고 확인이 필요한 입력으로 안내한다고 가정함. 이 정책들은 예시를 일관되게 설명하기 위한 설정이며 다른 과제에 자동 적용하는 기준이 아님.

제공 프로젝트를 유지하고 별도 서버나 저장소를 추가하지 않는 조회용 구현을 가정함. 데이터 처리 함수에서 만든 현재 기록에 같은 검색/필터 조건을 적용하고, 그 결과로 요약과 목록을 만듦. 상세는 선택한 요청 식별자로 같은 현재 기록을 찾음. 아래의 수정과 검증 사례도 이 가상 구현에 한정된 예시임.

## 잘못된 입력과 빈 결과

**예상 질문:** 데이터가 잘못됐거나 결과가 없는 경우에는 어떻게 동작하나요?

**답안 틀**

[오류 유형]과 [정상적으로 결과가 없는 상황]을 구분했습니다. [부분적으로 잘못된 입력]은 [유지하거나 거부하는 범위]를 정해 처리하고, [판단할 수 없는 값]을 정상 값처럼 바꾸지 않았습니다. [전체 처리를 계속할 수 없는 조건]에서는 [오류 안내]를 보여줍니다. 정상적인 빈 결과에는 [원인 설명과 다음 행동]을 제공하며, [복구 행동] 이후 결과가 돌아오는지도 확인했습니다.

**완성 예시**

## 요구 확인 이후의 변경

**예상 질문:** 처음 생각한 내용과 최종 구현이 달라진 부분은 무엇이며, 왜 바꿨나요?

**답안 틀**

이번 작업에서는 AI 제안을 수정하거나 기각할 만한 문제를 발견하지 못했습니다. 다만 제안을 그대로 믿기보다 [확인한 요구와 입력]을 기준으로 [실제로 점검한 결과]를 확인한 뒤 채택했습니다. [확인하지 못한 조건]은 남아 있으므로 제안 전체가 검증됐다고 설명하지는 않겠습니다. 조정한 사례 대신 어떤 기준으로 채택했고 어디까지 확인했는지를 설명할 수 있습니다.

**검증을 끝내지 못한 경우**

[구현한 처리]까지는 반영했지만 [검증하지 못한 조건]은 확인하지 못했습니다. 실제로 확인한 범위는 [실행한 명령이나 관찰한 화면]이며, 그 결과만으로 [더 넓은 동작]까지 정상이라고 판단할 수는 없습니다. 남은 확인은 [입력과 기대 결과]를 비교하는 것이고, 문제가 드러나면 [영향받는 업무 결과]를 먼저 수정해야 합니다. 따라서 현재 상태는 구현한 범위와 검증한 범위를 구분해 설명하겠습니다.

## 답변 후 대조

- 질문에서 요구한 선택 이유나 동작에 먼저 답했는지 확인함.
- 입력, 판단 규칙과 결과가 연결되며 실제 코드와 맞는지 확인함.
- AI가 처음 제안한 내용, 본인이 바꾼 내용과 바꾼 이유가 구분되는지 확인함.
- 실제로 실행하지 않은 검사, 받지 않은 답변이나 측정하지 않은 수치를 넣지 않았는지 확인함.
- 구현한 사실과 남은 한계를 구분하고, 기억나지 않는 이름을 지어내지 않았는지 확인함.
